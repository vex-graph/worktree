# Determinant — R3 Terminal Toolkit

Workspace checkout: `drivers/determinant`. Borrows R2 public contracts only.
Reusable terminal-cell rendering, widgets, CLI parsing and caller-fed input belong
here; app/session/consent policy and OS terminal lifetime belong to consumers/hosts.
Vexspoke retains bare one-line output and never calls this R3 toolkit.

Source layout: `src/ui/` is organised by capability (`surface`, `panel`, `text`,
`list`, `tree`, `field`, `code`, `markdown`, `button`, `image`, `scroll`,
`theme`), with `src/events/` for caller-fed input and `src/format/` for style
flags and colour. `src/cli/` stays outside `ui/`. The binding placement rule is
the repo lawbook's Source Taxonomy Extension.

| Feature | Status | Scope / proof / gaps |
| :--- | :---: | :--- |
| CLI extraction | 🟧 | Command, CommandParser, CommandRegistry, Scanner and LogCommands are being extracted from Vexspoke. Owner proof/integrated registration is pending completion of this cycle; legacy presence is not readiness. |
| Bare terminal UI toolkit | 🟧 | Canvas (four parallel glyph/style/fg/bg planes, clipped regions, `TerminalPen`), packed-`0xRRGGBBAA` colour **with real alpha** (`TerminalColor_over` composites a translucent layer over what is behind it, so a fade is a value rather than a per-theme constant; both ends are exact and opaque artwork passes through bit-for-bit), image→cells rasteriser (box sample, luminance ramp, per-cell colour), a bare region frame, generic list/text/input/status widgets, a scrollable tree of addressable rows, and shared per-axis scroll motion. Mirrored strict + ASan/UBSan owners under `tests/determinant/{cli,ui,events,format}` pass headlessly, including `terminal_color_test.c`, `terminal_tree_view_test.c` and `terminal_scroll_glide_test.c`. No application content (no chats/users/badges) lives here by design. Physical terminal, Unicode shaping, real TTY colour rendering and other platforms remain unproven; the toolkit composites a labelled backdrop, so a host that never resolves one still fades toward the host's stated fallback. |
| Mouse input decoder | 🟨 | `terminal_input`: the terminal's two mouse encodings (SGR and X10) decoded into one normalized `TerminalPointerEvent` in cells — move, drag, press, release, wheel up/down/left/right, with button and shift/meta/ctrl. Pure byte-at-a-time state machine: no I/O, no allocation, no clock, malformed sequences counted rather than logged. Proof: `tests/determinant/events/terminal_input_test.c` (literal byte strings, no terminal) under `python3 tests/determinant/run.py`. Gaps: nothing ROUTES these events — no component carries hover/pressed/grabbed state, and `TerminalPanel_childAt` is still uncalled outside its owner — so the inert/handle/control distinction the semicolon design asks for is application-side. X10 cannot carry motion, full modifiers, or a coordinate past 223; that is the encoding's limit, which is why SGR exists. |
| Layered panel, placement anchors and last-paint presenter | 🟨 | `TerminalAnchor` (FILL / four reserving bands / nine pins, pure placement returning region + cursor), the `TerminalPanel` **component tree** (two kinds: panel container and text leaf; FLEX flow and LAYERED stacking as one field; add/remove/detach with generation-stale ids; total repaint; self-add refusal and cyclic-paint refusal; cold doubling growth) and `TerminalSurface` (diff against the last paint, changed same-row runs through an injected sink, gap tolerance, atomic adoption). Proof: `tests/determinant/ui/panel/terminal_anchor_test.c`, `tests/determinant/ui/panel/terminal_panel_test.c`, `tests/determinant/ui/text/terminal_text_test.c` and `tests/determinant/ui/surface/terminal_surface_test.c` under `python3 tests/determinant/run.py` (strict + ASan/UBSan) and `./tools/b test`. Gaps: `terminal_frame` still owns its own band math and must be retired by migrating `TerminalRule` and the appearance presets; `SCROLL`/`CODE` flavours unimplemented; cycle safety proved for paint only, so teardown is undefined for an indirect cycle; child-array allocation failure unproved. |
| Terminal-cell renderer and reusable widgets | 🟧 | Foundation implementation and mirrored owners are in progress. `TerminalMarkdownView` delegates parsing to owning classes (`TerminalMarkdownTheme`, `TerminalMarkdownInline`, `TerminalMarkdownText`, `TerminalMarkdownTable`, `TerminalMarkdownCallout`, `TerminalMarkdownCodeBlock`, `TerminalMarkdownAction`) and keeps layout/paint: distinct per-level heading pens, italic through the 16-bit style plane, both callout spellings with indented bodies, aligned tables that honour escaped pipes and code spans, fenced copy/copy-check state and link hover/action cells. It draws the copy glyph but performs no clipboard write; the caller owns that action. `TerminalCodeView` paints caller-supplied ordered byte spans and virtual source-anchored hint labels into terminal cells; its owner proves colored/bold pens, hint placement, clipping, scroll and rejection preservation under strict C23 and ASan/UBSan via `tests/determinant/run.py`. Neither is a lexer or Semicolon integration. The markdown subset is not CommonMark: emphasis nesting, HTML, reference links and images are unowned. No physical terminal, Unicode shaping, other-platform or production Primeagen integration proof is claimed. |
| Resident terminal and replaceable view/command code | 🟧 | Host excludes active callbacks before admission/replacement and retains loaded-code lifetime. Owner tests must distinguish callback substitution from real loaded-module proof. This is not a native-code sandbox or broad app hot reload. |
| Scrollable, collapsible tree of rows | 🟨 | `terminal_tree_view`: a pre-order node array where a node's subtree is the contiguous range its `subtreeCount` claims, so folding is a jump and unfolding a step rather than a walk; visible rows are cached and recomputed only on a structural change; stable non-reused ids; folding, selection, `reveal` (open the path to a node), a clamped viewport, and click-to-node resolution by viewport offset. It draws NOTHING — a row comes back as data (label, depth, folder, expanded, selected) and the caller paints it, which is what lets one widget serve a file tree, a channel list and a menu. Proof: `tests/determinant/ui/tree/terminal_tree_view_test.c` under `python3 tests/determinant/run.py` (strict + ASan/UBSan) — the pre-order layout is re-derived from the visible rows, a 200-round deterministic fold fuzz checks that folding removes rows but never reorders them, and every scroll route is clamped including a fold under the viewport. Semicolon's rail consumes the widget and paints its returned rows; that host's scripted PTY rail tests own the integration evidence. Gaps: allocation failure is not injectable, so a refused growth is counted and diagnosed but never actually reached; the caller's painting is not part of the widget owner. |
| Per-axis scroll motion | 🟨 | `terminal_scroll_glide`: per-axis shown/target positions plus configurable easing and snap threshold; input moves only the target, one frame covers a fraction of the remaining distance, and `step` returns the whole-cell position to paint. It owns no cells and no clipping. Proof: `tests/determinant/ui/scroll/terminal_scroll_glide_test.c` under `python3 tests/determinant/run.py` (strict + ASan/UBSan) — defaults, configured construction, invalid ease/epsilon rejection with preserved state, impulse/target/position/halt/clamp, frame-by-frame easing and snap, null safety, projections, and a settled hot-loop guard. Semicolon consumes it for editor scrolling and supplies the document bounds; its scripted PTY scroll test exercises the route. Gaps: it is only the motion half — the `SCROLL` panel flavour with a real clip/offset is still unimplemented; physical-terminal appearance and non-macOS platforms remain unproved. |
| `TerminalApp` over the R1 host seam | ⬜ | Planned application composition (in the consuming app, not here): a generic `TerminalFrame` + the list/text/input/status widgets over the R3-defined opaque host seam, implemented on the R1 side by hotcwap `CommandLine` (owned TTY, always-honored resize, swappable app seam). Determinant stays bare — it ships geometry, widgets, cells, colour and image→canvas only. App content (chat wording, users, channels, command names, badges, `>w<` art) remains the application's. Stays R3 so a future R4 terminal panel can reuse it. |
| Primeagen consumer migration | ⬜ | Scheduled next: migrate reusable pieces while conversation/draft/consent/pipes/terminal stay resident. Reproduce restart-required `/update`, prove changed view/command in the same production process, preserve old state/code on rejection, and block resumption for unresolved rollback. Extraction alone does not fix this. |

Registered owner location: `../../../tests/determinant`. Exact executed commands, subject
hashes and gaps belong in `../test-checklist.md`; foundation scope does not imply
production readiness or physical/visual acceptance.
